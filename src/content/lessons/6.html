Recall first — no notes
What does a record generate for you, and why does that remove the Equals/GetHashCode hazard?

1. The Four You Will Use

the essentials
var list = new List<string> { "a", "b" };       // ordered, indexed, duplicates allowed
list.Add("c");
list[0];                                        // O(1) by index
list.Contains("b");                             // O(n) — scans

var map = new Dictionary<string, decimal>       // key → value, unique keys
{
    ["0123456789"] = 5000m,
};
map["0123456789"];                              // O(1)
map.TryGetValue(key, out var balance);          // safe — no exception if absent

var set = new HashSet<string> { "NGN", "USD" }; // unique, unordered
set.Add("NGN");                                 // returns false — already present
set.Contains("USD");                            // O(1)

decimal[] fixedSize = new decimal[3];           // array: fixed length, fastest
Dictionary indexer vs TryGetValue
map["missing"] throws KeyNotFoundException. map.TryGetValue(k, out var v) returns false instead. Use the indexer only when a missing key is genuinely a bug; use TryGetValue whenever absence is a normal possibility. Reaching for ContainsKey followed by the indexer does the lookup twice.

2. Choosing One

The habit worth forming
Accept the most general type, return the most specific useful one. Take IEnumerable<T> as a parameter so callers can pass anything; return IReadOnlyList<T> so callers get a usable result they cannot corrupt. Returning your internal List<T> hands out a handle to your own state.

If Contains on a List appears inside a loop, you have an O(n²) algorithm. Switching that list to a HashSet usually makes it O(n) with no other change — the most common easy performance win in C#.

3. LINQ

LINQ is a set of extension methods over IEnumerable<T> that let you describe what you want instead of looping to get it.

the same task, twice
// imperative
var big = new List<Account>();
foreach (var a in accounts)
    if (a.Balance > 1_000_000m) big.Add(a);
big.Sort((x, y) => y.Balance.CompareTo(x.Balance));

// LINQ
var big = accounts
    .Where(a => a.Balance > 1_000_000m)
    .OrderByDescending(a => a.Balance)
    .ToList();

First vs Single
First means "give me one, there may be others". Single means "there must be exactly one, and it is a bug if not". Using Single expresses an assumption and will tell you loudly when the assumption breaks — which is often what you want on a lookup by primary key.

4. Deferred Execution — The Thing That Catches Everyone

Most LINQ operators do not run when you write them. They build a query and wait.

the surprise
var numbers = new List<int> { 1, 2, 3 };
var query = numbers.Where(n => n > 1);   // nothing has executed yet

numbers.Add(4);

foreach (var n in query)
    Console.WriteLine(n);                 // 2, 3, 4  — it saw the addition

The query is a recipe, re-evaluated every time you enumerate it. Two consequences:

  • Results can change between building a query and using it, as above.
  • Enumerating twice does the work twice. If the source is a database or an HTTP call, that is two round trips.
the fix
var results = numbers.Where(n => n > 1).ToList();   // executes now, snapshot taken

ToList(), ToArray(), Count(), Sum(), First() and Any() all force execution immediately. Where, Select, OrderBy, Take and Skip do not.

The rule of thumb
Keep it deferred while you are still composing. Call ToList() once, at the point you need the values — and particularly before returning a query from a method, so the caller cannot accidentally re-execute it against a connection you have already disposed.

5. Grouping and Projection

a realistic query
var summary = transactions
    .Where(t => t.Date >= monthStart)
    .GroupBy(t => t.Currency)
    .Select(g => new
    {
        Currency = g.Key,
        Count    = g.Count(),
        Total    = g.Sum(t => t.Amount),
        Largest  = g.Max(t => t.Amount)
    })
    .OrderByDescending(x => x.Total)
    .ToList();

foreach (var row in summary)
    Console.WriteLine($"{row.Currency}: {row.Count} txns, {row.Total:N2}");

new { ... } is an anonymous type — a compiler-generated class for a shape you need once. Useful inside a method; you cannot return one from a method with a declared type, so use a record when the shape needs to cross a boundary.

6. Query Syntax

There is a second, SQL-like syntax. It compiles to exactly the same calls:

both are identical after compilation
var q = from t in transactions
        where t.Amount > 1000m
        orderby t.Date descending
        select t.Reference;

var q = transactions
        .Where(t => t.Amount > 1000m)
        .OrderByDescending(t => t.Date)
        .Select(t => t.Reference);

Method syntax is far more common and composes better. Learn to read query syntax — it appears in older code and is genuinely nicer for complex joins — but write method syntax.
