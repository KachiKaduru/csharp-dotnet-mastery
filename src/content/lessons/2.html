1. Value Types vs Reference Types

This is the concept to actually understand rather than memorise. Everything in C# is one or the other, and the difference is what the variable holds.

Value typesReference types
Variable holdsThe data itselfA reference to data elsewhere
Lives onThe stack, usuallyThe heap, always
AssignmentCopies the valueCopies the reference
Can be nullNo, unless int?Yes
Examplesint, double, bool, char, decimal, DateTime, any struct, any enumstring, arrays, any class, any interface, delegates
the difference, demonstrated
int a = 5;
int b = a;      // b gets a COPY
b = 10;
// a is still 5

var list1 = new List<int> { 1, 2, 3 };
var list2 = list1;   // list2 gets a copy of the REFERENCE
list2.Add(4);
// list1 now has 4 items too — both names point at one object
The bug this causes
Passing an object to a method and expecting the caller's copy to be untouched. It will not be — the method received the same reference and any mutation is visible to the caller. If you need isolation, copy deliberately.

2. The Types You Will Actually Use

TypeUse forNote
intWhole numbers32-bit. The default choice
longLarge whole numbers64-bit. IDs, timestamps, amounts in minor units
decimalMoneyBase-10, 28–29 digits. Slower, exact
doubleScientific, measurementsBase-2 floating point. Never money
booltrue / falseNot an integer. if (1) does not compile
stringTextReference type, but immutable — behaves value-like
DateTime / DateOnlyDates and timesPrefer DateTimeOffset when a time zone matters
GuidUnique identifiersGuid.NewGuid()
Never use double for money
0.1 + 0.2 == 0.3 is false for double, because base-2 cannot represent those values exactly. Over a million transactions the error compounds into a reconciliation break nobody can explain. decimal is base-10 and exact for decimal fractions. Use decimal, or store minor units (kobo, cents) as long.

3. var, const and readonly

declaration forms
var count = 10;                    // compiler infers int — still statically typed
var name = "Ada";                  // string
var items = new List<string>();    // List<string>

const int MaxRetries = 3;          // compile-time constant, baked into callers
static readonly DateTime Started = DateTime.UtcNow;   // set once at runtime

var is not dynamic typing. The type is fixed at compile time; you have only asked the compiler to work it out. var x = 5; x = "hello"; is a compile error.

const must be computable at compile time, so const DateTime Now = DateTime.UtcNow; will not compile. Use readonly for values fixed once at runtime.

A real gotcha with const
const values are copied into every assembly that uses them at compile time. Change a const in a library and recompile only the library — consumers keep the old value until they are rebuilt. static readonly is resolved at runtime and does not have this problem. For anything public that might change, prefer static readonly.

4. Nullable Reference Types

New projects ship with <Nullable>enable</Nullable>, and this is one of the best things about modern C#. The compiler tracks whether a reference can be null and warns when you ignore it.

the compiler is now on your side
string name = null;       // warning: cannot convert null to non-nullable
string? maybe = null;     // fine — the ? says "this can be null"

Console.WriteLine(maybe.Length);        // warning: possible null dereference
Console.WriteLine(maybe?.Length);       // null-conditional: returns null instead of throwing
Console.WriteLine(maybe?.Length ?? 0);  // null-coalescing: a default when null
OperatorDoes
? on a typeDeclares that null is allowed: string?, int?
?.Call only if not null, else the whole expression is null
??Use the right side if the left is null
??=Assign only if currently null
!"Trust me, not null." Silences the warning without checking anything
The null-forgiving operator is a loaded gun
maybe!.Length tells the compiler to stop warning. It does not make the value non-null — it converts a compile-time warning into a runtime NullReferenceException. Every ! is a claim you are making. Make very few.

5. Strings

the forms worth knowing
var name = "Ada";
var greet = $"Hello, {name}. You have {count:N0} messages.";   // interpolation, with format
var path  = @"C:\Users\dev\file.txt";                          // verbatim: no escapes needed
var json  = """
            { "id": 1, "name": "Ada" }
            """;                                               // raw string: quotes need no escaping

Strings are immutable. Every concatenation allocates a new string, so building one in a loop allocates once per iteration:

why StringBuilder exists
var s = "";
for (int i = 0; i < 10_000; i++) s += i;      // 10,000 allocations

var sb = new System.Text.StringBuilder();
for (int i = 0; i < 10_000; i++) sb.Append(i);
var result = sb.ToString();                    // one buffer, grown as needed

Comparison traps worth knowing now: use string.IsNullOrWhiteSpace(s) rather than s == "", and pass StringComparison.OrdinalIgnoreCase explicitly when comparing case-insensitively — culture-sensitive comparison is the default in some APIs and produces different answers in different locales.

6. Methods

signatures and parameter forms
public decimal Fee(decimal amount, decimal rate = 0.015m)   // optional parameter
{
    return amount * rate;
}

// named arguments — order no longer matters, and the call reads clearly
var f = Fee(rate: 0.02m, amount: 5000m);

// expression-bodied, for one-liners
public decimal Double(decimal x) => x * 2;

// out: return a second value
public bool TryParseAmount(string input, out decimal amount)
    => decimal.TryParse(input, out amount);

if (TryParseAmount("12.50", out var parsed))
    Console.WriteLine(parsed);

Overloading means several methods sharing a name with different parameter lists. The return type is not part of the signature — two methods differing only by return type will not compile.

The Try... pattern above is idiomatic C#: a bool for success and an out for the value, used wherever failure is expected rather than exceptional. You will see it on every parsing API in the framework.
