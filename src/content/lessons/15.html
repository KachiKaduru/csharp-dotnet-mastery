1. ILogger Is Already There

No package, no configuration. Inject ILogger<T> and the category is set to T automatically — which is what later lets you raise the level for one class without drowning in everything else.

injection
public class TransferService
{
    private readonly ILogger<TransferService> _logger;

    public TransferService(ILogger<TransferService> logger) => _logger = logger;
}
Console.WriteLine is not logging
It has no levels, no timestamps, no destinations, no context, and it writes synchronously to a stream nobody is reading. It works on your machine and tells you nothing in production.

2. The Levels, And When Each Is Right

LevelUse forExample
CriticalThe application cannot continueCannot reach the database at startup
ErrorAn operation failed and a human should actTransfer failed after all retries
WarningUnexpected, but handledRetry 2 of 3 succeeded; circuit breaker opened
InformationSignificant business events. On in productionTransfer initiated; transfer completed
DebugDiagnostic detail. Off in productionWhich branch was taken, request shape
TraceVery fine detail. Almost never on. May contain sensitive dataEvery field mapped
The judgement that separates useful logs from noise
Error means someone should act. If a line fires every few minutes and nobody ever does anything, it is not an error — it is Warning or Information. Leaving it as Error trains the whole team to ignore the alerts that matter. A log where everything is an error is a log nobody reads.

3. Structured Logging — Use The Template

the single most important habit on this page
// WRONG — string interpolation
_logger.LogInformation($"Transfer {reference} of {amount} completed");

// RIGHT — named placeholders
_logger.LogInformation("Transfer {Reference} of {Amount} completed", reference, amount);

These look almost identical and behave very differently:

  • The interpolated version produces a unique string every time. A log aggregator sees a million distinct messages and cannot group or query them.
  • The templated version keeps the message constant and attaches Reference and Amount as queryable fields. You can then ask for "all logs where Amount > 1000000" — which is the entire point of structured logging.
  • It is also cheaper: with interpolation the string is built even when the level is disabled.

Placeholders are matched by position, not by name, so the argument order must match the template order. The names are for the output, not the binding.

4. Scopes — Correlating One Request

One request touches a controller, a service, a repository and an HTTP client. Under load, hundreds interleave in the log file. Without something tying them together you cannot reconstruct a single operation — which is the whole job during an incident.

a scope adds context to everything inside it
using (_logger.BeginScope("Transfer {Reference}", request.Reference))
{
    _logger.LogInformation("Validating");
    await _validator.CheckAsync(request, ct);

    _logger.LogInformation("Debiting {Account}", request.Source);
    await _accounts.DebitAsync(request.Source, request.Amount, ct);

    _logger.LogInformation("Completed");
}
// every line above carries Reference, without repeating it

ASP.NET Core also gives every request a TraceIdentifier automatically. Include it in responses — particularly error responses — so a customer complaint arrives with the exact key to find the request:

new ProblemDetails { Extensions = { ["traceId"] = HttpContext.TraceIdentifier } }
Log durations on every external call
"The transfer was slow" is unactionable. "The core banking call took 8.2 seconds" is a conversation with another team. It is also the only way to know whether your timeout value is sensible.

5. Logging Exceptions Properly

pass the exception, do not stringify it
catch (HttpRequestException ex)
{
    _logger.LogError("Transfer failed: " + ex.Message);          // loses the stack trace
    _logger.LogError(ex, "Transfer {Ref} failed", reference);    // keeps it — exception FIRST
}

The exception is the first argument, with no matching placeholder. ex.Message alone frequently returns something useless, and discards the stack entirely — which is how you end up with the log line Transfer failed: and nothing to go on.

Two more rules: log it or rethrow it, not both (otherwise the same trace appears at three layers and triples log volume during an incident), and never swallow silently.

6. What You Must Never Log

Logs are shipped to aggregators, pasted into tickets, and read by people with no business seeing customer data. In a regulated environment this is a compliance matter, not a style preference.

NeverLog instead
Full card numbersFirst 6 and last 4: 539983******1234
Full account numbersLast 4, or an internal reference
Passwords, PINs, OTPsNothing. Not masked, not at Debug
Tokens, API keys, auth headersNothing, or a short hash if you must correlate
National IDs, full names with balancesA customer id resolvable in a controlled system
Whole request or response bodiesThe specific fields you need
The trap
_logger.LogDebug("Request: {Request}", request) looks harmless and is the most common way sensitive data reaches a log file — because serialising the object includes everything in it. Log named fields, not objects.

7. Configuration

appsettings.json
{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "MiniBank.Transfers": "Debug",
      "Microsoft.AspNetCore": "Warning",
      "Microsoft.EntityFrameworkCore.Database.Command": "Information"
    }
  }
}

Levels are set per category, which is the payoff for injecting ILogger<T>: you can turn your own namespace up to Debug in production for ten minutes without the framework burying you. That last line logs EF's generated SQL — the N+1 detector from the previous page.

8. Logs, Metrics, Traces And Health

ToolAnswers
LogsWhat happened to this request? Individual events, high detail
MetricsHow is the system doing overall? Rates, counts, latency percentiles
TracesWhere did the time go across services? Distributed tracing
Health checksShould the load balancer send traffic here?

Do not grep logs to answer "what is our p99", and do not consult a dashboard to debug one transaction. A correlation id is the poor version of a trace, and for a long while it is enough.

health checks
builder.Services.AddHealthChecks()
    .AddDbContextCheck<AppDbContext>()
    .AddUrlGroup(new Uri("https://core.internal/health"), name: "core-banking");

app.MapHealthChecks("/health/live");    // am I running?
app.MapHealthChecks("/health/ready");   // can I serve traffic?

Keep liveness and readiness separate. Liveness should not check dependencies — if it does, a database blip makes the orchestrator kill otherwise healthy instances, turning a degradation into an outage.
